# 02 · 使用指南

## 日常流程

1. 在 opencode 聊天里看到不懂的内容，**鼠标普通拖选**（松开即自动复制；若未开 copy-on-select，则拖选后右键一次）
2. 按 **Alt+L**（终端聚焦时生效）
3. 编辑器右侧显示连接服务、选取上下文、发送等步骤，就绪后展示 `你的原文 → 讲解`，流式输出
4. 可在窗口里直接打字追问；讲解会话与主会话完全隔离

**失败信号**：错误原因直接显示在讲解面板上（剪贴板为空时另有两声提示音）；完整脚本日志见输出通道「opencode-tutor」。

## 学习会话生命周期

> 学习线是**独立目录里的根会话**（目录为 `%LEARN%\lines`，不在任何项目文件夹里）——
> 因此它**不会出现在任何项目的会话列表里**（TUI/Web 列表按项目目录过滤，天然排除），
> 也不会被 TUI 当作子会话内联渲染进主会话时间线；讲解窗口通过深链照常访问。
> 早期版本（≤0.2 子会话机制）的旧线会在下一次触发时迁移为该形态，旧线及历史保留。

| 问题 | 答案 |
|---|---|
| 一个学习会话活多久？ | 记录持久保存。每个主会话对应一条当前学习线，未达到历史阈值时复用追加；达到阈值后续建新会话 |
| 为什么会话列表里看不到它？ | 会话列表按**项目目录**过滤（服务端 `?directory=`），学习线住在独立的 `%LEARN%\lines` 目录，任何项目列表都不含它 |
| 什么时候消失？ | 只有你主动删除时才消失。建线和迁移均不自动删除历史 |
| TUI 里能进到学习线吗？ | 不能（也不再需要）：它不是任何会话的子会话，不在子会话导航里。讲解窗口是唯一入口——这正是"零污染"的来源 |
| 会无限膨胀吗？ | 主会话背景按完整消息选取，新安装默认 12000 字符。学习历史默认达到 40 条消息或 60000 文本字符时，下次 Alt+L 新建会话；旧记录不删除。阈值不在 Web UI 内直接追问时执行 |
| 怎么重置？ | 点击“新会话讲解此选区”，或执行“新学习会话讲解选区”命令。只更新当前主会话映射，保留旧线和其他主会话映射；上一会话按钮可在浏览器查看旧记录 |
| 换主会话了会怎样？ | 新主会话自动获得自己的新学习线，互不干扰；讲解面板每次都打开**本次触发**的学习线（扩展按当次标记取 URL，无滞后） |
| 旧版子会话学习线怎么办？ | 无需操作：该主会话下一次 Alt+L 会新建独立根线，旧子会话及其问答历史保留；其他主会话映射不受影响 |

## 多实例 / 多项目

- 每个**项目目录 + 主会话**一条独立学习线（state.json 记录映射）
- 后台服务与会话存储是全局的：任何 opencode 实例/终端触发都能用
- 4399 端口被占用时：改 `%LEARN%\config.json` 的 `port` 后首次触发会自动拉起新端口服务；**旧端口的常驻服务不会自动停止**，请手动结束或重启一次

## 讲解方式、背景与取消

- Alt+L 保持一键操作。命令“选择讲解方式和背景”可为本次选择简短、深入、举例，以及相关背景、近期对话、仅选区；面板“换种方式讲解”复用面板中的原文。
- 面板“新会话讲解此选区”沿用当前讲解方式和背景范围；新的 Alt+L 使用设置中的默认值。退出方式选择框会保留当前会话和停止生成按钮。
- 默认值可在 VS Code 设置 `opencodeTutor.explanationStyle` 和 `opencodeTutor.contextMode` 中调整。面板显示扫描消息数、实际采用消息数、字符数与预算。字符预算不是精确 token 或费用估算。
- 相关背景优先定位选区原文，其次匹配关键词；未定位时使用近期消息。过大的单条消息整体跳过，不截断代码块或 Unicode 字符；原选区仍原样发送。
- “仅选区”不读取主会话背景，但现有学习历史仍是模型上下文。要完全重新开始，使用新会话。
- “取消准备”协作停止尚未发送的请求，不强制终止后台服务。若取消到达时已发送，面板明确提示并保留会话入口；“停止生成”只中止当前学习会话，可能同时影响另一个窗口对此学习会话的生成。关闭面板不会自动中止已发送的生成。
- 发送超时或网络错误时不自动重发；面板保留可用的学习会话入口，先检查是否已收到，避免重复提交。

运行配置位于 `%LEARN%\config.json`，缺省值如下；已有配置不会在升级时被覆盖：

| 字段 | 默认值 | 用途 |
|---|---:|---|
| backgroundMaxChars | 12000 | 主会话背景字符上限，0 为不附背景，最多 60000 |
| contextPageSize | 40 | 每页消息数，1–100 |
| contextMaxMessages | 200 | 最多扫描消息数，不低于一页，最多 500 |
| learningMaxMessages | 40 | 学习历史消息数阈值，2–200 |
| learningMaxChars | 60000 | 学习历史文本字符阈值，1000–300000 |
| selectionMaxChars | 24000 | 选区字符上限，1–60000；超出时提示缩小选区 |

历史扫描仅使用服务返回的分页游标。旧服务不返回游标时只读取第一页；不会退回无界读取，也不会猜测游标。新建学习会话不会复制旧问答或自动调用模型摘要，旧记录通过上一会话入口保留。

## 更换讲解模型

**方式一（推荐）**：编辑 `~/.config/opencode/opencode.json` 中 `agent.explain.model` → 保存 → 在服务空闲时手动重启后台后生效；工具不会按端口强制结束现有进程。

**方式二（傻瓜旋钮）**：编辑 `%LEARN%\config.json` 加一行 `"model": "<provider>/<model>"` → 立即生效（请求级覆盖，无需重启任何东西）。

> 模型串格式：`providerID/modelID`；若 modelID 本身含 `/`（如 zenmux 的 `deepseek/deepseek-v4-flash`），写 `zenmux/deepseek/deepseek-v4-flash`——脚本按第一个 `/` 切分，支持嵌套 id。

## 幽灵“Session not found”角落通知（一次性清理）

场景：讲解窗口正常显示，但角落弹「Session not found: ses_xxx」（一个从未出现在地址栏的 id）。

原因：Web UI 在 localStorage 里记忆“上次当前会话”，若该会话早已被清理/从未持久化，每次加载都会顺手 fetch 一次而 404。

解决（一次性）：
1. 打开 `http://127.0.0.1:4399/` 首页
2. 在会话列表里**点进你的 📘 学习线**（它在独立的 `lines` 目录分组下；或直接按一次 Alt+L 打开深链）
3. 此后应用的当前会话指针更新为真实 id，通知不再出现

## 换电脑 / 重装

迁移以下位置即可（最省事：clone 仓库后跑一遍 `install.ps1 -WithPrewarm`）：
- `~/.config/opencode/opencode.json`（agent 配置）
- `~/.config/opencode/learn/`（脚本 + config.json；state.json 可丢，会自动重建）
- VS Code 侧：keybindings（alt+l → opencodeTutor.open）+ settings（copyOnSelection）+ 讲解面板扩展（`extension\` 目录 → `~\.vscode\extensions\`）
- 环境变量（`setx OPENCODE_EXPERIMENTAL_DISABLE_COPY_ON_SELECT 0`）
- 可选：注册登录+保活计划任务
